# Mine Duel v0.3.1-web — 온라인 PvP

기존 CPU 모드를 유지하며 온라인 1:1 대전을 별도 화면에 추가했다. 서버 운영 및 로컬 개발은 [ONLINE-PVP.md](../ONLINE-PVP.md)를 참고한다.

## 로컬 실행

Node.js 22 이상 권장. 저장소 루트에서:

```sh
npm run start --prefix web
```

http://127.0.0.1:4173/web/ 에서 플레이합니다. 파일을 더블클릭하는 file:// 실행은 ES Modules 때문에 지원하지 않습니다.
다른 정적 서버로 web 또는 docs 폴더를 제공해도 됩니다. 런타임 외부 의존성이 없으므로 게임 실행에 npm 설치는 필요하지 않습니다.
테스트용 서버는 localhost에만 연결합니다. 같은 Wi-Fi의 실제 휴대폰 검사는 별도 LAN 서버 또는 배포 URL을 사용하세요.

## 규칙 및 구현

- 초기·일반 지뢰 설치는 동일하게 미공개·마커 없음·자기 지뢰 없음 조건을 사용한다. 상대 지뢰와 중첩 가능하며 인접 숫자는 점유 셀당1이다.
- 일반 턴은 한 칸 탐색 → 지뢰 하나 설치 → 턴 종료. 자기 지뢰 탐색은 거절하며 상대 지뢰를 탐색하면 패배. 0 자동 공개 없음.
- 자기 지뢰에 재설치 금지. 상대 지뢰 중복 설치 허용. 주변 숫자는 지뢰가 있는 칸을 한 번만 계산하며 설치 후 즉시 갱신. 중복 여부 별도 통지 없음.
- 마커는 미공개 칸에만 설치, 기존 지뢰 위에도 가능. 턴당 최대 1개 신규 설치, 자기 마커만 제거. 제거해도 횟수 복구 없음. 마커 칸은 탐색/설치 차단.
- 최초 탐색자는 계속 저장됩니다. 플레이어 #BBD7FF / CPU #FFBDBD, 숫자는 #18263C.
- CPU는 안전·불확실을 우선한다. 두 후보가 없으면 남은 마커로 확정 지뢰에 마커를 놓고, 횟수가 없으면 확정 후보도 탐색한다. CPU 전용 무승부는 없다. 난이도40/20/5%, 설치60/25/15%, 턴 종료 마커70%다.
- CPU 설치 전략은 60% 전체 무작위 / 25% 최근 플레이어 탐색 주변 / 15% 모든 공개 칸 주변. 해당 후보가 없으면 전체 무작위. 초기 설치도 상대 지뢰와 중첩을 허용.
- CPU 탐색/설치/마커 결정에는 Game/Board 참조를 전달하지 않습니다. Game의 private board에서 만든 동결된 관측값만 전달하며 숨겨진 상대 지뢰 소유권이 없습니다.
- CPU가 지뢰를 밟으면 승리, 플레이어는 패배. 미공개 칸이 모두 마커로 막히면 즉시 무승부. 필수 설치가 불가능해도 무승부. 자기 마커 제거로 설치가 가능하다면 제거 기회를 유지.
- 인간·CPU의 자기/공유 지뢰 탐색은 거절하며 상태를 유지한다. 상대 지뢰만의 셀을 탐색하면 해당 행동자가 패배한다.
- 모든 미공개가 마커로 막히면 자기마커를 제거할 수 있어도 즉시 무승부가 우선합니다. 추론의 모순은 CPU 예약 정지와 오류 안내로 처리하고 자동승패 규칙을 추가하지 않습니다.
- 최초 접속은 언어 선택 → 번역된 규칙 → 난이도 선택 → 게임 시작. 한국어/일본어/영어/중국어 간체를 지원하고 `mineDuel.language`에 선택을 저장합니다. 저장소 접근이 차단되어도 현재 세션은 실행됩니다.
- 상단 ☰ 메뉴에서 규칙, 재시작 확인, 언어 변경. 게임 중 언어를 바꿔도 보드/난이도/턴/마커 횟수는 유지됩니다. 재시작은 확인 후 새 규칙 안내와 기본 난이도 보통으로 돌아가며 언어를 유지합니다.
- 모든 팝업은 CPU 남은 지연을 보존하고 보드 입력을 막습니다. 시작 언어/규칙 팝업은 외부 터치로 닫히지 않습니다. 나머지 팝업은 외부 터치/닫기로 복귀하며 내부 스크롤과 구분됩니다. CPU 타이머 세대 번호로 이전 게임의 예약 작업을 무효화합니다.
- native dialog의 모달 입력 차단/포커스 제한, 접근성 이름, 실제 button, 키보드 조작 지원. 결과 화면에서도 메뉴 접근 가능.
- Safe Area, visualViewport/dynamic viewport 변화 대응. 작은 세로 화면에서는 보드 크기를 남은 높이에 맞춰 조절합니다. 지나치게 낮은 화면 및 가로 화면은 스크롤을 허용해 칸을 과도하게 축소하지 않습니다.
- 화면 터치는 touch-action:manipulation으로 더블탭 확대 오조작을 줄입니다. 규칙 본문은 세로 터치 스크롤 가능. 접근성을 위해 핀치 확대를 강제로 막지 않습니다.

## 테스트

```sh
npm ci --prefix web
npm run build --prefix web
npm test --prefix web
npm exec --prefix web -- playwright install chromium webkit
# 다른 터미널에서 로컬 서버가 실행 중인 상태로:
npm run test:browser --prefix web
```

Node 내장 테스트 46개로 규칙, 소유권, 중복 숫자, 마커, 승패/무승부, CPU 정보 차단/난이도/설치 전략, 지연 보존/취소된 작업 무효화, 번역 키/치환 인자/저장 예외, 버전 확인/오프라인 처리, 배포 파일 연결을 검사합니다. 기존1,500판과 마커를 포함한 추가600판,추론28,499관측 검사를 포함합니다. 해당 자동표본을 실제 플레이어 승률로 사용하지 않습니다.
Chromium 및 WebKit의 모바일 터치 에뮬레이션과 PC 화면에서 실제 UI를 검사합니다. 보고서 및 캡처는 로컬 web/test-results/ (Git 제외)에 생성됩니다. 실물 Android/iPhone 검증을 대신하지 않습니다.

## GitHub Pages

web/은 원본, docs/는 배포본입니다. 로컬에서 `npm run build --prefix web`로 docs를 갱신합니다.
배포본은 CSS와 모든 ES Module의 내용 및 의존성에 따라 해시 파일명을 생성합니다. 최상위 스크립트뿐 아니라 내부 import URL도 바뀝니다. 이전 해시 파일은 보존하여 캐시된 HTML/모듈이 새 배포 후에도 로딩되게 합니다.

`version.json`은 config의 VERSION에서 자동 생성되며 시작 시, 60초마다, 탭이 다시 보일 때 `cache: no-store`와 고유 쿼리로 확인합니다(5초 제한). 새 버전 안내는 기존 팝업이 닫힌 뒤 표시합니다. 나중에를 선택하면 같은 버전을 이번 세션에 다시 권하지 않으며 게임을 유지합니다. 업데이트를 선택하면 `?v=<배포 버전>` URL로 새로고침하여 HTML 캐시 영향을 줄입니다. 자동 새로고침은 하지 않습니다. 네트워크 오류는 게임에 영향을 주지 않습니다.

GitHub Pages의 HTML 캐시 헤더는 직접 제어할 수 없습니다. 업데이트 전의 v0.1.1 HTML이 이미 캐시된 브라우저는 새 버전 감지 기능이 없으므로 첫 업그레이드 때 일반 새로고침 또는 `?v=0.2.1-web` 접속이 필요할 수 있습니다. Service Worker는 사용하지 않습니다. 오래된 해시 파일은 작고 민감 정보가 없으며, 계속 보존하므로 배포 폴더 크기는 업데이트에 따라 늘어납니다.

저장소 Settings → Pages → Build and deployment → Source를 **GitHub Actions**로 선택하세요.
포함된 `.github/workflows/pages.yml`은 main push 시 web을 빌드하고 규칙 테스트를 통과한 docs만 배포합니다. Actions 탭에서 수동 실행도 가능합니다.
배포가 완료되면 Settings → Pages에 실제 URL이 표시됩니다. 이후 같은 저장소/main에 web 수정사항을 커밋하고 push하면 같은 URL에서 최신 버전이 제공됩니다.
공식 안내: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages

Actions 대신 branch 배포를 선택하려면 Source를 Deploy from a branch, main /docs로 설정하세요. 이 방식은 매번 로컬 build 후 docs 변경사항까지 커밋해야 합니다. 자동 workflow와 branch 배포를 동시에 쓰지 마세요.

## 파일 구조 및 업데이트

- index.html, css/style.css: 다국어 화면, 팝업, 모바일 레이아웃.
- js/i18n.js: 네 언어 UI/규칙 번역, 저장 검증, 한국어 fallback. 로컬 개발 서버에서 누락 키 경고.
- js/updates.js, version.json: 배포 버전 확인과 오류 격리.
- js/config.js: 웹 버전, 보드 설정, 난이도 확률, 설치 전략 비율.
- js/board.js: 칸 상태 및 인접 계산. js/game.js: 단일 규칙 모델/턴/종료.
- js/ai.js: 관측 기반 추론/CPU 선택 및 분리된 실행기.
- js/timer.js: CPU 대기 일시 정지/재개. js/ui.js, js/main.js: UI/이벤트.
- scripts/build.mjs: 상대 경로를 유지하는 해시 배포본 생성.
- scripts/serve.mjs: 원본 및 /mine-duel/ 하위 경로 배포본 로컬 서버.
- tests/: Node 규칙 테스트와 브라우저 자동 테스트.
- package.json, package-lock.json: 개발용 테스트 의존성. 게임 런타임에는 포함하지 않습니다.

버전 변경은 js/config.js의 VERSION에서 합니다. 코드를 바꾸면 리소스 해시는 버전 변경 여부와 무관하게 갱신됩니다.
현재 Unity 폴더 내에 웹 파일과 별도 Git 저장소 mine-duel/이 함께 있다면 GitHub Desktop이 사용하는 mine-duel/web을 수정해 push하거나, 프로젝트 web 변경을 mine-duel/web에 복사한 뒤 커밋하세요.
Unity 파일, APK, 인증서/키스토어, .codex 원격 첨부, node_modules는 배포본에 포함하지 않습니다.

## MVP 범위

페이지 새로고침 시 새 게임(언어만 저장). CPU 모드는 새로고침하면 새 게임을 시작한다. 온라인 대전은 별도 Worker/SQLite DO가 상태를 저장하고 같은 브라우저에서 세션 복귀를 지원한다. 회원 계정, 사운드, Service Worker는 미구현이다.
최신 Android Chrome/iOS Safari를 대상으로 하며, native dialog/ES Modules/private class fields 지원이 필요합니다.


## 캐시 안정화 후보

v0.2.3-web에서 도입한 캐시 안정화 처리를 유지한다. 업데이트 쿼리로 해당 실행 버전에 진입했을 때만 이 프로젝트의 기본 HTML을 cache:reload로 한 번 갱신한다. HTTP 캐시와 브라우저 방문 기록/BFCache는 다르며, 새 코드가 실행되지 않는 기존 HTML을 소급 수정하지 못한다. 진행 중 게임 자동 이동·Service Worker·저장 형식 변경은 없다. 이전 서버 버전은 업데이트로 안내하지 않는다.

## v0.3.1 종료 보드 및 대전 기록

- CPU 결과 팝업의 보드 보기 → 결과 보기로 같은 최종 보드를 반복 확인한다. 온라인은 기존 결과 영역을 접고 다시 펼친다. 종료 보드 입력은 계속 차단되며 공개 범위는 기존 규칙과 같다.
- 턴 수는 오프닝을 제외한 양측 일반 턴 번호다. 마지막 진행 중인 턴과 시간 초과 턴을 포함한다. 오프닝 중 기권·무효는 0턴이다.
- CPU는 게임 시작 버튼부터 종료 모델 판정까지 실제 경과 시간(메뉴·백그라운드 체류 포함)을 기록한다. CPU 행동 지연의 일시 정지와 경과 시간은 별개다.
- 온라인은 서버의 시작·종료 시각으로 기록한다. 재접속·백그라운드 시간도 포함되며 종료 후 고정된다. 시작 시각이 없는 이전 서버 결과는 시간을 추정하지 않고 기록 정보 없음으로 표시한다.
- 소요 시간은 MM:SS, 1시간 이상 HH:MM:SS이며 초 미만은 버린다. 영구 전적·리플레이 기능은 추가하지 않는다.
- 서버 저장 구조에 startedAt, result.record를 추가했다. 기존 schema·프로토콜·세션·보드·결과 보관 정책은 유지한다. 서버를 먼저 배포한 후 정적 프런트엔드를 배포한다.
